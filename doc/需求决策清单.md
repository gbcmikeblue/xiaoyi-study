## 一、这份文档是什么

前期分析已确认：本仓库目前只有两份调研文档，没有代码、数据与 Schema。选型结论（用聪聪学堂的管线、hanzi-study 起步、Strokes 参照架构）已经给出，但从「选谁」到「怎么做」之间缺少一系列**只能由需求方拍板**的决定。

本文把这些待决点整理为 34 个问题，每题包含：**提问 → 背景 → 可选方向 → 建议**。

### 使用方式

1. 在每题末尾的 `决策：` 后填写选项字母（可多选，用 `/` 分隔），或直接口头告知。
2. 不确定的写 `暂缓`，我会按"建议"项继续推进并在后续文档标注为假设。
3. 优先级含义：**P0** = 阻塞后续所有设计与排期，必须先答；**P1** = 影响架构与工作量估算；**P2** = 可在开发过程中补齐。

## 三、A 组：定位与范围

### Q01 首期交付形态与封装方案

**优先级**：P0　**关联**：G5、报告§4

**背景**：报告中四种交付形态（Android App / iOS+iPad / H5+PWA / 课堂大屏）的约束各不相同：H5 快但离线与推送弱，App 需商店资质，课堂大屏是另一套固定舞台。首期只能主攻一种，其余降级或推迟。这个决定直接锁死技术栈与后续所有排期。

**问题**：首期以哪种形态交付，其余形态如何处理？

**可选方向**：

- A. **H5/PWA 优先** — 一周内可上线，无需商店审核，可随时热更新；弱在离线可靠性、家长信任度、无推送。
- B. **Capacitor 封装三端** — 一套 Web 代码出 Android / iOS / iPad，保留 H5 作为第四形态；需自备签名与开发者账号。
- C. **uni-app 一套四端** — 含微信小程序（家长触达率高），生态成熟；工程约束大，原生能力受插件市场限制。
- D. **课堂一体机大屏优先** — courseware-engine 路线，固定 16:9 舞台 + 单文件离线放映；不适配竖屏平板。

**建议**：B，同时保留 H5 作为试玩入口。理由：报告已确认 Capacitor 比 HBuilderX 云打包更可控，且不放弃平板体验。

**决策：**：B

### Q02 目标用户与角色边界

**优先级**：P0　**关联**：G1

**背景**：全文反复出现"用户"，但从未定义是谁。角色决定权限模型、账号体系与数据可见范围：只做学生端可全离线；加家长端就必须有账号与学情归集；加教师端就要有班级概念，进而触发跨设备同步与儿童数据合规。

**问题**：产品面向哪些角色，各自能看到什么、能做什么？

**可选方向**：

- A. **仅学生** — 单机使用，家长在旁边看不看无所谓，无账号、无权限体系，最轻。
- B. **学生 + 家长** — 家长可看学习记录、设时长限制；需家长账号与绑定关系。
- C. **学生 + 家长 + 教师** — 教师建班、发作业、看班级学情；需班级模型与云端数据。
- D. **再加校级管理员** — 多班级/多学科汇总报表，典型 To B 形态。

**建议**：C 作为首期目标，D 在数据模型上预留字段但不实现。理由：报告的差异化卖点之一就是"补齐候选项目集体缺失的教师端"。

**决策：**： A

### Q03 核心使用场景优先级

**优先级**：P0　**关联**：G5

**背景**：报告把家庭自学、课堂投屏、课后作业、单元测评四类场景混在两条落地路径里讲，导致功能优先级无法排序。四类场景对交互的要求互斥：课堂投屏要求大字号、远距离可读、教师单点操控；家庭自学要求小屏精细交互与语音引导；测评要求防作弊与计时。

**问题**：首期重点服务哪个场景？其余场景是"兼容"还是"明确不做"？

**可选方向**：

- A. **家庭自学/预习复习为主** — 学生自主点读、练习、闯关。
- B. **课堂投屏教学为主** — 教师主导，一体机横屏播放。
- C. **课后作业/巩固为主** — 教师或家长布置，学生完成，有提交与反馈。
- D. **单元测评为主** — 计时、判分、错题归集、成绩单。

**建议**：A + C（可多选）。这两类共享同一套"内容 + 练习 + 记录"内核，B 与 D 可后续叠加；若首期做 B，则 A 的精细交互基本作废。

**决策：**： A

### Q04 首期学科范围与册次

**优先级**：P0　**关联**：G3

**背景**：报告的核心判断是"真正差距在内容，不在代码"——北师大版数学、一年级沪教版英语、深圳地方课程三块无人做过。全 7 科一起做会把首期变成纯内容工程，且无法验证产品形态。册次的选择则影响是否半年后推倒重来。

**问题**：首期做几科、覆盖哪些册？

**可选方向**：

- A. **只做数学（北师大版）单科打穿** — 内容最能形成差异化，范围最窄。
- B. **数学 + 英语** — 正是报告点名的两块硬缺口，差异化最强，且英语内容量小于语文。
- C. **语文 + 数学 + 英语** — 主科齐全，家长感知完整；内容量约为 B 的 2.5 倍。
- D. **全 7 科 + 地方课程** — 完整覆盖，但首期周期至少翻倍。

册次维度：

- ① 仅上册　② 仅下册　③ 上下册全量

**建议**：B + ③。一年级上下册内容量差异不大，只做一册会在半年后被迫重做一次内容管线；数学+英语恰好覆盖两块硬缺口。

**决策：**： C + ③

### Q05 走快速 MVP 还是完整平台

**优先级**：P1　**关联**：G12

**背景**：报告给了两条路径：A 用 4–6 周出可用版，B 用 3–4 个月做完整平台。但路径 B 要同时完成 7 科内容灌注、账号体系、教师端、三端封装四件独立的大事，"3–4 个月"缺乏依据（前期分析中已标记为 G12）。

**问题**：选择哪条路径，以及是否接受对工期的重新评估？

**可选方向**：

- A. **只走路径 A** — 先拿到可试用的最小闭环，验证内容与形态再决定是否投入。
- B. **直接走路径 B** — 一次性建成平台，避免二次重构；风险是周期与内容工作量双重不确定。
- C. **A 先行、B 紧随** — A 的产物（Schema、内容库、三端壳）作为 B 的种子，不做返工。
- D. **先只做 PoC，不排产品期** — 用 1–2 周验证三个候选项目能否在目标设备跑通，再定路径。

**建议**：C。但需注意：选 C 的前提是路径 A 阶段就把 Schema 与内容目录定死，否则 A 会变成一次性原型。

**决策：**：A

### Q06 分发方式与商业模式

**优先级**：P2　**关联**：G10、G11

**背景**：分发方式决定合规成本：校内私有分发几乎零资质门槛；上架国内商店需软著与主体资质；上架 App Store 需开发者账号且儿童类应用审核严格。商业模式则决定是否必须做付费、退款、发票与家长端账单。目前报告只把软著、ICP 备案列为"风险"，未进入计划。

**问题**：首期如何分发，是否收费？

**可选方向**：

- A. **校内/私有分发，免费试用** — 不经商店，扫码或内网安装，最快；无收入。
- B. **学校采购（To B）** — 需软著、资质、合同与发票能力；单价高、决策链长。
- C. **家长付费订阅（To C）** — 需支付通道、退款规则、未成年人付费限制。
- D. **暂不定，先做演示版** — 仅用于内部评审与试点沟通。

**建议**：A 起步，同时启动软著申请（周期长，宜早）。理由：首期目标是验证内容与形态，不是变现。

**决策：**：A

## 四、B 组：内容与教材基准

### Q07 深圳教材基准的权威出处

**优先级**：P0　**关联**：G2

**背景**：整份报告最硬的判据是"数学北师大版、英语沪教版且一年级开设"，但依据只有一句"sz.gov.cn 公开附件"，无文号、无链接、无适用学年。教材选用目录逐年调整，缺年份等于判据随时失效。此外报告把全市视为统一版本，未讨论民办校、国际部、各区差异。

**问题**：教材基准以什么为准？由谁提供？

**可选方向**：

- A. **我提供官方目录文件或链接** — 附文号与适用学年，我据此更新报告。
- B. **由你检索政府公开渠道并标注来源** — 我自行找文件、标注链接与年份，你复核。
- C. **不绑定单一版本，做成"教材版本可切换"** — 内容层按课标组织，版本作为映射层；容错性最好，但设计成本高。
- D. **以某几所试点校的实际用书为准** — 最贴近真实教学，但样本代表性需说明。

**建议**：A 或 B 先锁定权威版本，同时在 Schema 中保留"教材版本"字段（即 C 的降级实现），避免后续换版重做。

**决策：**：A

### Q08 内容缺口的量化口径

**优先级**：P0　**关联**：G3

**背景**：报告只说"缺数学、英语、道法、音乐、美术、地方课程"，没有数字。这导致三个关键问题无法回答：要重做多少内容、需要几个人月、能复用候选项目的哪些部分。没有这张表，任何工期估算都是猜测。

**问题**：缺口统计做到什么粒度？

**可选方向**：

- A. **只统计册数与单元数** — 半天可出，只能做粗略判断。
- B. **统计到 单元 → 课时 → 知识点 三级** — 3–5 天，可直接用于排期与分工。
- C. **统计到题量、音频数、插图数** — 最精确，工作量最大，适合进入开发前再做。
- D. **不做统计，边做边看** — 不推荐。

**建议**：B。产出一张「7 科 × 上下册 × 单元/课时/知识点」矩阵，逐格标注"可复用 / 需改造 / 需全新"。

**决策：**：B

### Q09 课程 Schema 的层级粒度

**优先级**：P0　**关联**：G4、D7

**背景**：报告路径 A 第 1 步就是"抽出统一的课程数据 Schema"，但只列了 `学科/年级/册/单元/课时/知识点/题型` 七个词，没有层级关系、字段定义与示例。同时全文"模块/知识点/课时"三种说法混用，mini-classroom 的"23 个知识点"与聪聪学堂的"4448 个课时"显然不是同一量级。

**问题**：Schema 定到几层？是否同时产出 JSON Schema 与示例数据？

**可选方向**：

- A. **4 层最简** — 学科 → 册 → 单元 → 课时。够跑通内容展示，测评与自适应要后补。
- B. **5–6 层，含知识点与题型/难度** — 支持错题归集、难度分级、周报统计。
- C. **B + 课标素养标签** — 可对齐教学要求与教研口径，适合进校场景。

**建议**：B，并在字段中为 C 预留扩展位（tags 数组）。配套产出：`schema/*.json`（JSON Schema）、`schema/example.json`（一课完整示例）、术语表。无论选哪项，都建议同时产出 JSON Schema，否则"统一 Schema"仍是口号。

**决策：**：B

### Q10 内容生产方式与审核准入

**优先级**：P1　**关联**：G7、S9

**背景**：报告点名聪聪学堂"3.4 万道题由 AI 生成、教师逐题审核尚未完成"，却把它的数据管线列为复用对象——这意味着同样的问题会被继承。一年级学生没有辨别错题的能力，错题造成的认知损伤不可逆，因此审核不是可选项，而是准入门槛。

**问题**：内容怎么生产，审核到什么程度才允许上线？

**可选方向**：

- A. **复用开源内容并改造** — 最快，但需逐题校验，且数学/英语内容本身要重做。
- B. **AI 生成 + 人工全量审核** — 质量最稳，人力成本最高。
- C. **AI 生成 + 抽检（如 20%）+ 上线后错题回收** — 平衡；需配套"报错"入口与修正流程。
- D. **纯人工编写** — 质量可控，速度最慢。

**建议**：C，但数学与英语（首期核心）采用 B 的标准，语文/科学等可复用部分采用 C。同时定义三件配套：谁审核（学科教师资质）、抽检比例、错题从上报到修正的时限。

**决策：**：A

### Q11 语音与图片素材策略

**优先级**：P1　**关联**：G7

**背景**：一年级产品高度依赖语音（识字量低，文字提示基本无效）。聪聪学堂有 11.9 万个 MP3，courseware-engine 用 macOS `say` 生成语音（跨平台不可复现），hanzi-study 是本地音频。素材策略直接影响包体、音质、制作周期与版权。

**问题**：语音与插图怎么来？

**可选方向**：

- A. **全部 TTS 合成**（如 Edge TTS） — 成本接近零、可批量、可随内容变更即时重生；音质与情感表现一般。
- B. **关键素材真人录音，其余 TTS** — 跟读示范、课文朗读用真人，指令与反馈用 TTS；成本与效果平衡。
- C. **复用开源音频** — 零成本，但需逐个核对许可，且版本对不上教材。
- D. **插图全部自绘/重绘** — 版权唯一安全路径，也是最贵的一项。

**建议**：B；插图不设选项——按报告的红线（不复刻课本原页），必须自绘或采购可商用图库。

**决策：**：A

### Q12 教材版权边界与操作定义

**优先级**：P0　**关联**：S8

**背景**：报告存在一处口径冲突：一边推荐用 tchMaterial-parser + ChinaTextbook 做"深圳版教材电子化的素材获取与比对"，一边要求"不随包分发原页"。什么算"内部"、比对产出的结构数据能否入库、PDF 存放位置与访问控制、批量下载平台电子课本的条款风险，全部没有操作级定义。这是最容易出事的一项。

**问题**：教材 PDF 在本项目中的合法使用边界如何划定？

**可选方向**：

- A. **红线：不复刻课本原页，全部按课标重绘** — 最安全，工作量最大。
- B. **允许内部比对：仅提取目录/结构，PDF 不入库、不进代码仓、不随包分发** — 需要明确的存放与访问规则。
- C. **主动联系出版社取得授权** — 最正规，周期长、费用不确定，适合规模化后。
- D. **完全不用教材 PDF，只依据公开课标与教学大纲** — 风险最低，但内容与课本贴合度下降。

**建议**：A 作为产品红线 + B 作为内部调研的操作方式（PDF 只存本地受控目录，结构数据以人工整理的 Markdown 入库）。C 在确定商业化后再启动。

**决策：**：B

## 五、C 组：技术架构与实现

### Q13 技术底座选型

**优先级**：P0　**关联**：报告§6

**背景**：报告给了三个可复用来源，但三者的架构互不兼容：聪聪学堂是 Next.js + TS 的完整工程（体积大、依赖重），hanzi-study 是无构建的静态站（单文件页面级、无 Schema），mini-classroom 是手写 `wordData.js` 的数据站。把它们"组合"起来的实际成本，报告中未评估。

### Q14 离线与内容分发策略

**优先级**：P0　**关联**：E3、S2

**背景**：这是报告里最尖锐的资源冲突：聪聪学堂建议 ≥100 GB 磁盘、11.9 万个 MP3，而一年级学生实际使用的平板多为 32/64 GB，可用空间可能不足 10 GB。同时报告又把"完全离线"（hanzi-study）列为核心优势。二者不能同时满足，必须定策略。

**问题**：离线做到什么程度？内容如何分发到设备？

**可选方向**：

- A. **全量预装** — 一次装完，体验最好；安装包或首次下载体积巨大，低端机可能直接失败。
- B. **按册/按单元按需下载 + 断点续传 + 空间预检** — 平衡方案；需要下载中心与失败重试的完整设计。
- C. **在线优先 + 本地缓存** — 包体最小，弱网与无网教室场景不可用。
- D. **A 与 B 混合**：核心册次预装，扩展内容按需下载** — 复杂度最高。

**建议**：B，并在首页给"当前占用空间 / 剩余空间"的可见提示。

**决策：**：A

### Q17 多端进度同步策略

**优先级**：P1　**关联**：E2

**问题**：采用哪种同步模型？

- D. **服务端权威记录 + 本地队列重放** — 最严谨，工程量最大。

**建议**：B 作为首期（明确告知"以最新设备为准"），数据结构按 C 设计，避免后期改表。

**优先级**：P1　**关联**：E4

**可选方向**：

- D. **不做处理** — 不推荐。

**建议**：A + B 组合：每学期一个内容快照，快照内做版本号与迁移，跨学期只保留汇总统计。

### Q21 录音/手写过程中的中断处理

**优先级**：P1　**关联**：E5

**问题**：中断后如何处理中间态？

**可选方向**：

- C. **后台继续录音/记录** — 系统限制多（iOS 尤其），不可靠。
- D. **B + 关键操作前主动提示（如"离开将丢失本次录音"）** — 最稳。

**建议**：D。

**决策：**：B

### Q26 WebView 壳的安全基线

**优先级**：P0　**关联**：S4

**背景**：报告提到聪聪学堂 Android 端是"WebView 在线壳"——这是最容易被忽视的风险点：远程加载的 JS 一旦被劫持或篡改，就能读取本地学情、注入内容。对儿童产品而言，这属于不可接受的风险等级。

**问题**：壳的安全基线定到哪一级？

**可选方向**：

- A. **强制 HTTPS + 前端资源打包内置** — 基础要求，仍可能被中间人替换远程接口。
- B. **A + 安装包签名校验 + 禁用明文 HTTP + 禁用 file:// 协议** — 常规加固。
- C. **B + 前端资源完整性校验（SRI/哈希清单） + 接口证书固定（pinning）** — 金融级，成本略高。
- D. **完全不使用 WebView 壳，原生或纯 H5 浏览器访问** — 规避风险但放弃离线与设备能力。

**建议**：C。儿童产品的安全下限应高于普通应用。

**决策：**：A

### Q27 儿童个人信息合规与数据安全

**优先级**：P0　**关联**：S5、S6

**背景**：报告只写了"《儿童个人信息网络保护规定》、不得默认采集、离线优先最稳"三句，属于名词级别。真正要落地的是：监护人同意的取得方式、最小化字段清单、留存期限、注销与删除通道、未成年人模式的具体形态。另外一旦上云，班级数据的横向越权（改个 ID 就能看别人家孩子）必须有设计级防护。

**问题**：采集边界与防护等级如何定？

- B. **最小必要（昵称 + 班级码），家长同意后使用** — 满足教学功能，合规可控。
- C. **手机号实名 + 学籍信息** — 便于找回与校内管理，合规成本最高。

**第二部分：数据安全**

- ① 本地明文（现状）　② 本地加密 + 云端鉴权与班级隔离　③ ② + 操作审计日志

**建议**：B + ②。理由：A 与 Q15/Q16 的决策冲突；C 在试点期没有必要。

**决策：**：A

## 八、F 组：文档、测试与项目治理

### Q29 本仓库自身的许可

**优先级**：P0　**关联**：D1

**背景**：这份调研的核心议题就是别人的开源许可，但仓库本身没有 LICENSE，默认"保留所有权利"——意味着同事或合作方无法合法复用这份结论。属于低级但影响面大的缺口。

**问题**：本仓库（文档类）采用什么许可？

**可选方向**：

- A. **保持现状（无 LICENSE）** — 仅内部使用，外部不可复用。
- B. **CC BY-NC 4.0** — 允许署名非商业复用，符合"调研资料"属性，防止被他人拿去商用。
- C. **CC BY 4.0 / MIT** — 最开放，利于传播。

### Q30 检索策略与评分可复现性

**优先级**：P1　**关联**：D3、D4

**问题**：是否补齐可复现性材料？

- B. **补量化评分矩阵**（教材匹配度/许可/跨端/内容规模/活跃度/二次开发成本，带权重） — 结论有据。
- C. **B + 原始数据 CSV + 检索日志（关键词、日期、筛选条件、排除原因）** — 完全可复现。
- D. **C + 自动复检脚本**（定期拉 star/最近提交） — 报告可自动保鲜。

**建议**：C。D 可作为后续自动化项。

### Q31 证据等级与 PoC 实测验收

**优先级**：P0　**关联**：G9、D5、G8

**问题**：是否对候选项目做真机实测？验收以什么为准？

### Q32 风险矩阵与责任人

**优先级**：P1　**关联**：D6

**背景**：现有风险只覆盖"许可与合规"一列，缺少技术风险（WebView 兼容、离线包过大）、进度风险（内容重绘工作量）、内容风险（AI 错题）、组织风险（教材审核依赖校方）。且所有风险都没有责任人与触发条件，等于没有管理。

**问题**：是否建立风险矩阵？

**可选方向**：

- A. **只列风险清单** — 现状。
- B. **概率 × 影响 二维矩阵 + 责任人 + 缓解措施 + 触发信号** — 可跟踪。
- C. **B + 每月复盘机制** — 适合长周期项目。

**建议**：B；若确定走路径 B（3–4 个月），升级为 C。

**决策：**：A

### Q33 测试范围

**优先级**：P2　**关联**：D8

**背景**：项目尚无代码，谈不上测试用例；但测试范围现在不定，后续就会出现"内容错了没人发现"（拼音标注、笔画顺序、答案正确性）这类最致命的问题——这类错误靠人工点检很难覆盖。

**问题**：现在就确定测试范围，还是开发后再说？

**可选方向**：

- A. **开发后再定** — 短期省事，内容质量无保障。
- B. **现在定范围**：内容校验（拼音/笔画/答案）、多端兼容、离线、性能、无障碍 — 五类，不写用例。
- C. **B + 优先做内容自动化校验脚本**（如 pypinyin 逐字比对、答案一致性检查） — 同时解决内容质量与测试空白。

**建议**：C。courseware-engine 已有 pypinyin 注音校对的做法，可直接借鉴。

**决策：**：C

### Q34 文档版本与结论有效期

**优先级**：P1　**关联**：D9、E11

**背景**：选型报告里的 star 数、提交时间、教材版本都是快照，教材目录每年 4–8 月可能调整。报告没有任何"何时失效"的说明，也没有变更记录，半年后引用会产生误导。

**问题**：如何管理文档时效？

**可选方向**：

- A. **不标注** — 现状。
- B. **标注适用学年 + 复核触发条件（教材目录更新 / 候选项目重大版本 / 许可变更）+ CHANGELOG** — 低成本，效果好。
- C. **B + 每学年 8 月固定复核并出版本号** — 制度化。

**建议**：C。

**决策：**：B
