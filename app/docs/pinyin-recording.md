> 用途：把真人老师朗读的拼音接入项目，替代当前用汉字读音代替字母发音的做法

## 二、间隔时长怎么定

**每个拼音之间停顿 2 秒**，开头与结尾各留 3 秒空白。

这个 2 秒是三重约束的结果：

| 约束 | 要求 | 说明 |
|---|---|---|
| 下限 | ≥ 0.45 秒 | 拆分脚本判定"分隔"的最短静音（`--min-silence`）。低于这个值，两段会被判为同一音节 |
| 心理 | ≥ 1.5 秒 | 老师需要换气、看下一行的余量，1 秒以下容易越读越快导致后期漏读 |
| 上限 | ≤ 3 秒 | 太长会让整段录音过久，63 项 × 3 秒 = 3 分钟纯静音，没必要 |

2 秒留了 4 倍余量，正常发挥不会踩到下限。**如果中途停顿明显偏短，脚本会检测到段数变少并报错，不会写错文件。**

## 三、录制方法

### 3.1 设备与环境

| 项 | 建议 |
|---|---|
| 设备 | 手机录音 App 或电脑 + 麦克风；音质比设备更重要 |
| 环境 | 小房间、关窗、关空调风扇；避免大厅、瓷砖卫生间这类强混响空间 |
| 距离 | 嘴到麦克风 15–20 cm，偏 45° 避开气流直吹 |
| 电平 | 正常说话音量即可，不要贴太近（会削波），也不要太远（信噪比低） |

### 3.2 格式

**必须录成 WAV（16-bit PCM），单声道或立体声都可以，采样率 16 kHz 以上。**

- Android 录音机 App 一般在设置里可选 WAV；
- iPhone 自带录音是 m4a，需要转码：

```powershell
ffmpeg -i 录音.m4a -ac 1 -ar 16000 -acodec pcm_s16le pinyin.wav
```

（本机 ffmpeg 尚未安装，若需要我可以再试一次安装；也可以用在线转换工具）

### 3.3 朗读要领

1. **先试读前 5 个**，回放确认音量和环境没问题，再录全部；
2. **只读字母的音，不要念示范字**。例如第 1 项读"玻"的音（b），不要念出"玻"这个字；
3. **声调读第一声**，平而稳，不要拖长也不要上扬；
4. **每个音节读一遍**，不要重复。读错了不要紧，整段重录比剪辑更可靠；
5. **停顿用默数**：读完一个，心里数"一、二"，再读下一个；
6. 全程保持同一距离和音量，中途不要移动手机。

### 3.4 录完自检

- 时长应与 `63 × 2.4 秒 ≈ 2.5 分钟` 接近（每项 0.4 秒发音 + 2 秒停顿）；
- 明显短很多 → 中途读快了或漏读；
- 回放跳着听 3 处，确认没有串音、咳嗽、手机震动声。

## 四、拆分

### 4.1 先看切分结果，不写文件

录音放到 `recordings/incoming/` 后，可以省略 `--input`（目录规范见 `docs/recordings-layout.md`）：

```powershell
cd d:\project\sz-grade1-h5-edu-research\app
python scripts/split_pinyin.py --dry-run
```

输出示例：

```
音频时长 151.20s，采样率 16000Hz
检测到语音段 63 个，清单需求 63 个

--dry-run：切分结果预览
  01-b       b       0.40s
  02-p       p       0.41s
  ...
```

段数一致即可进入下一步。

### 4.2 段数不一致怎么办

脚本会**拒绝写文件**，并打印每段的起止时间与时长，方便定位问题：

| 现象 | 原因 | 处理 |
|---|---|---|
| 段数偏少 | 某两处停顿太短被合并 | 对照诊断里的时间点找到位置，重录那一段 |
| 段数偏少且整体很短 | 漏读 | 核对清单 |
| 段数偏多 | 首尾杂音、咳嗽被当成语音 | 裁掉开头结尾，或提高 `--threshold-db` 到 -35 |
| 段数偏多且中间零碎 | 环境噪声大 | 换安静环境重录，或降低 `--threshold-db` |

可调参数：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--threshold-db` | -40 | 静音判定阈值，噪声大时调高（如 -35），误判时调低 |
| `--min-silence` | 0.45 | 判为分隔的最短静音，秒 |
| `--merge-gap` | 0.22 | 小于此值的间隙视为音节内部，防爆破音被切碎 |
| `--min-voice` | 0.10 | 短于此值的片段丢弃，秒 |
| `--padding` | 0.06 | 每段前后保留的留白，秒 |

### 4.3 正式拆分

```powershell
python scripts/split_pinyin.py
```

输出到 `public/content/yw-1a/pinyin/`，文件名 `01-b.wav` … `63-ying.wav`。

拆分成功后，原始录音会自动从 `incoming/` 移到 `processed/`，文件名前加时间戳，避免重复处理同一个文件。

> 脚本用 `selftest_split.py` 生成过 63 段模拟音频做回归验证：151 秒输入被正确切成 63 段，每段 0.40 秒，与清单一一对应。

## 五、交付成果

拆分完成后得到 **63 个独立 wav 文件**，命名与清单 `file` 字段严格对应：

```
public/content/yw-1a/pinyin/
├── 01-b.wav      02-p.wav      ...
├── 15-zh.wav     16-ch.wav     ...
├── 29-v.wav      （ü 在文件名中用 v 代替）
├── 37-ve.wav     （üe）
├── 43-vn.wav     （ün）
└── 63-ying.wav
```

单声道 16-bit，采样率继承录音源（建议 16 kHz）。

### 接入课时内容

课时 JSON 的 `audio` 区块直接用 `src` 指向文件，`src` 优先级高于自动查表：

```json
{
  "type": "audio",
  "src": "/content/yw-1a/pinyin/09-g.wav",
  "text": "g",
  "caption": "听 g 的音"
}
```

`chars` 与 `words` 区块的条目也支持 `audioSrc`，同样优先于自动查表：

```json
{ "char": "a", "pinyin": "ā", "audioSrc": "/content/yw-1a/pinyin/24-a.wav" }
```

### 体积参考

63 个 wav 约 **2–3 MB**（16 kHz / 16-bit / 平均 0.6 秒）。若需要压到三分之一，可转 flac：

```powershell
ffmpeg -i 01-b.wav -c:a flac 01-b.flac
```

## 六、常见问题

**Q：一定要真人录吗，现在的 TTS 不能用？**
TTS 读英文字母 `a` 会读成英语发音，读汉语拼音 `a` 又缺乏音节感。拼音教学对"教具音"的要求比课文高，真人录音最稳。当前项目用汉字读音（如用"衣"代替 i）是权宜之计。

**Q：能不能只录当前用到的 9 课，不录满 63 项？**
可以，把 `pinyin-list.json` 里不需要的条目删掉，顺序保持连续即可。但建议一次录完——拆开录意味着要重跑整个流程。

**Q：录错了某一项怎么办？**
两种做法：整段重录（推荐，5 分钟的事），或单独补录一项后手工命名覆盖对应文件（快，但要保证文件名对得上序号）。

**Q：麦克风有底噪，切出来带杂音怎么办？**
先看 `--threshold-db` 是否合适；切完若仍有底噪，用 Audacity 的"降噪"统一处理，或在录音前关掉风扇空调重录。

**Q：拆分后某段明显比别的长或短？**
说明那段前后停顿异常。看 `--dry-run` 的时长列表，重录该位置即可。单音节正常在 0.35–0.8 秒之间。
