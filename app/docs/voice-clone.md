# Ming-3 零样本音色克隆使用指南

> 适用版本：Ming-3.0-tts 0.5B（ComfyUI 原生移植）
> 编写日期：2026-10-31 ｜ 依据：本机实测 + 官方 cookbook
> 适用项目：一年级学习 H5（`sz-grade1-h5-edu-research`）

---

## 一、这份文档解决什么问题

把某位真人老师的声音克隆下来，用于批量生成课文朗读、讲解与反馈语音，使全站语音保持同一位老师的声音。

技术上属于**零样本克隆（zero-shot voice cloning）**：不需要训练，只要一段参考录音和它的逐字文稿，模型即可复现音色。核心代价不在技术，而在**授权**——所以第三章的篇幅比操作步骤更长。

> 本文所有命令均在本机实测通过（2026-10-31，ComfyUI 0.43.0 / torch 2.12.1+cu130 / RTX 5060 Ti）。

## 四、参考音频规范

克隆质量的上限由参考音频决定，参数调不了这一层。

### 4.1 硬性要求

| 项 | 要求 | 原因 |
|---|---|---|
| 时长 | **10–30 秒**，1–3 句完整话 | 太短音色不稳，太长显著增加编码与 prefill 时间 |
| 人数 | 单人，全程同一人 | 多人会让音色"混叠" |
| 背景 | 无音乐、无键盘声、无回声、无他人说话 | 噪声会被当作音色特征一起复现 |
| 采样率 | ≥ 16 kHz，单声道 | 电话录音（8 kHz）音色会发闷 |
| 音量 | 稳定，不削波 | 忽大忽小会带出音量抖动 |
| 语速 | 自然，接近日常讲课速度 | 参考语速会影响生成语速倾向 |
| 内容 | 含目标音色的典型音高与语气，避免只有"嗯""好的" | 模型从这段音频学音高分布 |
| 格式 | wav / flac / mp3 均可，**建议 wav** | 减少解码差异 |

### 4.2 转录文本要求

`reference_text` 是**参考录音里说的话**，不是要生成的新句子。这是最容易搞错的一处。

- 必须**逐字一致**，包括语气词
- 建议带标点（帮助模型对齐停顿）
- 不要修正口语（老师说"这个"就写"这个"，不要改成书面语）
- 不要补录音里没有的字

**转录错了会怎样**：模型会把错误的文字强行对齐到音频上，表现为生成语音语速拖沓、吞字、音色漂移、句尾上扬。这是克隆失败最常见的原因，占问题的一大半。

### 4.3 录制建议

- 安静小房间，手机距离嘴 15–20 cm，避开空调与风扇
- 先录一段空白环境音，便于后期判断噪声底
- 让老师自然朗读一段教材内容（而非念数字或字母表），这样音色更接近实际使用场景
- 同一位老师建议录 2–3 条不同语气的样本（平稳朗读 / 提问 / 鼓励），后续可按场景切换

### 4.4 文件放置

放到 ComfyUI 的 input 目录，**用英文文件名**（中文名在某些节点链路上会出编码问题）：

```
D:\Comfy-Desktop\ComfyUI-Shared\input\teacher_ref.wav
```

## 五、操作流程

### 5.1 第一步：登记克隆工作流（只需一次）

工作流文件 `ming_dub_clone.json` 中 `audio` 输入在两个节点重名（LoadAudio 与 SaveAudioAdvanced），直接传参会报歧义错误，因此必须先登记别名并显式绑定。

```powershell
$COMFY = "C:\Users\Administrator\.codebuddy\skills\comfyui-local\scripts\comfy.py"
$WF    = "C:\Users\Administrator\.codebuddy\skills\comfyui-local\scripts\workflows\ming_dub_clone.json"

python $COMFY register ming_clone --source "file:$WF" `
  --param audio=1.audio `
  --param text=3.text `
  --title "Ming-3 音色克隆"
```

登记结果写入 skill 的 `registry.json`，之后直接按别名调用即可。

> 注意：`task.reference_text` 这类**含点号的输入名不能写进 `--param`**（绑定语法按最后一个点切分，会误判成节点 `3.task`）。这类参数留空，调用时用完整输入名传值，走自动绑定。

### 5.2 第二步：单条试生成

先用一句短文本验证音色，再批量。

```powershell
python $COMFY run ming_clone `
  -p "audio=teacher_ref.wav" `
  -p "text=小明今天学会了三个字。" `
  -p "task.reference_text=大家好，我是李老师，今天我们一起学习第一课。" `
  --out .\clone-test --timeout 300 --json
```

成功时 stdout 返回：

```json
{"ok": true, "files": [{"path": "...\\clone-test\\...flac", "kind": "audio", "bytes": 96561}]}
```

**本机实测**：单条 7.2 秒（含参考音频编码），输出 44.1 kHz 单声道 flac，约 96 KB。

### 5.3 第三步：批量生成

单条命令逐个跑适合验证；批量请走项目脚本（见第六章）或循环调用：

```powershell
$texts = @("天在上，地在下。", "我们一起来读一读。", "答对了，真棒！")
$i = 0
foreach ($t in $texts) {
  $i++
  python $COMFY run ming_clone -p "audio=teacher_ref.wav" -p "text=$t" `
    -p "task.reference_text=<参考录音逐字稿>" --out ".\out\$i" --json | Out-Null
}
```

### 5.4 第四步：接入项目

产物替换 `public/content/<册>/audio/` 下的音频，并更新 `audio-manifest.json`。项目的 `scripts/tts_batch.py` 提供 `comfy` 引擎统一处理这一步（见第六章）。

## 六、参数说明

### 6.1 模型加载（MingLoadModel）

| 参数 | 取值 | 说明 |
|---|---|---|
| `model` | `Ming-3.0-tts-0.5b` / `...-int8-convrot` / `tiny-9b` / `tiny-9b-int8-convrot` | 0.5B 足够克隆；Tiny 9B 仅多人对话需要 |
| `precision` | `auto` | 跟随 ComfyUI 的设备与精度选择 |
| `device` | `auto` | 自动选 cuda |
| `download_if_missing` | `false`（默认） | 保持 false，避免误触发大文件下载 |

### 6.2 生成（MingGenerate）

| 参数 | 本机取值 | 说明 |
|---|---|---|
| `task` | `clone` | 克隆任务；另有 `ip`（内置音色）、`voice_design`（文字描述造音）、`basic`（只克隆音高/语速/音量，不需文稿）、`emotion`、`dialect` |
| `task.reference_audio` | 参考录音 | 音色来源 |
| `task.reference_text` | 逐字稿 | **参考录音**的文字，不是新句子 |
| `task.language` | `Chinese` | **新语音**的语言；参考音频可以是别的语言 |
| `text` | 待合成正文 | 要读的新内容 |
| `seed` | `42` | 固定可保证同文本多次生成一致；想换语气可小范围变动 |
| `cfg` | `2.0` | 引导强度，越高越贴文本、越低越自然，建议 1.8–2.2 |
| `flow_steps` | `10` | 求解步数，提高会增加时长，10 是质量与速度的平衡点 |
| `sigma` | `0.25` | 仅在 `temperature > 0` 时起作用 |
| `temperature` | `0.0` | 0 表示关闭随机噪声，批量场景建议保持 0 保证一致性 |
| `max_steps` | `250` | **单段上限约 20 秒**；长文本会被切分，超过会截断 |
| `trim` | `true` | 去掉尾部静音 |

### 6.3 语音控制（仅 `basic` / `emotion` / `dialect` 任务可用）

| 参数 | 可选值 |
|---|---|
| `speed` | `慢速` / `中速` / `快速` |
| `pitch` | `低` / `中` / `高` |
| `volume` | `低` / `中` / `高` |
| `emotion` | `高兴` / `悲伤` / `愤怒` / `恐惧` / `厌恶` / `惊讶` / `中性` |
| `dialect` | `cantonese`（粤语） / `chuanyu dialect`（川渝话） |

> `clone` 任务不接受上述控制参数。需要"克隆音色 + 控制语速"时，改用 `basic` 任务（同样给参考音频，但不需要转录文本），代价是音色相似度略低于 clone。

### 6.4 与内置音色的取舍

| 维度 | 克隆（clone） | 内置音色（ip，如灵小萌） |
|---|---|---|
| 音色来源 | 指定真人 | 模型自带 100+ 音色 |
| 一致性 | 依赖参考音频质量 | 天然稳定 |
| 授权成本 | **需要书面授权** | 无 |
| 生成耗时 | 约 7 秒/条（含参考编码） | 约 3.9 秒/条 |
| 适用场景 | 有固定授课老师、需品牌化声音 | 无特定老师、快速上线 |

## 七、效果验证

### 7.1 客观检查（生成后立即看）

| 检查项 | 方法 | 异常表现 |
|---|---|---|
| 时长合理 | 中文约 4 字/秒。10 字文本应约 2.5 秒 | 明显过长 → 转录不匹配；过短 → 被截断 |
| 是否截断 | 长文本（>80 字）分段生成 | `max_steps 250` 上限约 20 秒，超出部分丢失 |
| 文件可播 | 播放器能打开、波形不为空 | 0 字节或全静音 → 提交参数错误 |
| 采样率 | 44.1 kHz 单声道 | 采样率异常 → 模型加载有问题 |

### 7.2 主观检查（必须人工听）

建议做**盲听 A/B**：把「参考录音原声」与「克隆生成」随机编号，请不了解技术细节的人判断哪段是真人。若判断接近随机，说明克隆质量合格。

逐项听四件事：

1. **音色相似度**：像不像同一个人（最重要）
2. **发音准确度**：多音字、数字、姓名、轻声字是否读错
3. **自然度**：有无机械停顿、句尾上扬、气口怪异
4. **一致性**：同一文本生成 3 次，听是否像同一人在同一状态下说的

### 7.3 常见失真与对策

| 现象 | 主要原因 | 对策 |
|---|---|---|
| 语速拖沓、吞字 | 转录文本与录音不符 | 重新逐字核对 `reference_text` |
| 音色忽男忽女 | 参考音频含多人 | 重新录制单人样本 |
| 底噪明显 | 录音环境有空调/风扇 | 换安静环境，或先用降噪处理 |
| 句尾上扬、像在提问 | 参考音频本身是问句结尾 | 换一段陈述句为主的样本 |
| 长句后半段变调 | 超出单段时长被切分 | 按标点拆成短句分别生成 |
| 情绪平淡 | `temperature=0` 且 `cfg` 偏低 | 适当提高到 `cfg 2.2`，或换 `emotion` 任务 |

## 八、常见问题

**Q1：报「参数 audio 在多个节点上存在（1, 4）」**
工作流里 `LoadAudio` 和 `SaveAudioAdvanced` 都有 `audio` 输入。按 5.1 登记别名并 `--param audio=1.audio` 显式绑定。

**Q2：报「参数绑定的节点 id 不存在：3.task」**
`--param` 的绑定语法按最后一个点切分输入名，`3.task.reference_text` 会被解析成节点 `3.task`。含点的参数不要写进 `--param`，留给自动绑定，用完整名传值。

**Q3：生成出来不像参考音频**
按可能性排序：① 转录不匹配（最常见）② 参考音频有噪声 ③ 参考时长过短（<5 秒）④ `cfg` 过低。先核对转录。

**Q4：长文本被截断**
`max_steps 250` 对单段约 20 秒。按标点手动拆句，逐句生成后再拼接；或减小 `flow_steps` 换取更长单段。

**Q5：生成速度慢**
单条 7 秒属正常（参考音频编码占大头）。参考音频从 30 秒缩到 15 秒可明显提速；重复使用同一参考时，ComfyUI 会复用已编码结果。

**Q6：显存不够 / 报 OOM**
0.5B 约需 2.5–2.8 GiB。关掉同时运行的其他大模型；或改用 `int8-convrot` 权重；仍不够则换 `tiny` 之外的更小配置。

**Q7：能不能直接克隆中文老师去读英语**
可以。`task.language` 控制**输出**语言，参考音频可以是中文。但跨语言时音色保持度会下降，英语课建议单独用英文样本或内置英文音色（`US_Stella`）。

**Q8：Whisper 自动转录不可用**
本机未安装 Whisper 权重。手动填 `task.reference_text` 即可，不需要 Whisper。若坚持自动转录，需放 `models/whisper/large-v3-turbo/` 或开 `download_if_missing`（约 1.5 GB）。

**Q9：生成的声音可以对外分发吗**
取决于授权书。默认**不允许**把参考音频或克隆模型打进对外 APK；仅"生成后的音频"在授权范围内可用于项目内部教学。

**Q10：老师不授权了怎么办**
按授权书的撤回条款执行：停止生成、下架相关音频、删除参考样本与派生产物，并在归档记录中登记撤回时间与处理结果。

## 九、落地到本项目

### 9.1 与项目脚本的对接

`scripts/tts_batch.py` 的 `comfy` 引擎通过 skill CLI 调用，只需在 `scripts/tts_config.json` 里指定别名与参数映射：

```json
{
  "skill_comfy_py": "C:\\Users\\Administrator\\.codebuddy\\skills\\comfyui-local\\scripts\\comfy.py",
  "alias": "ming_clone",
  "param_text": "text",
  "param_voice": null,
  "extra_params": {
    "audio": "teacher_ref.wav",
    "task.reference_text": "参考录音的逐字稿"
  },
  "timeout": 300
}
```

> `param_voice` 为 `null` 表示该别名不使用音色名参数（克隆任务的音色来自参考音频）。
> 内置音色模式（`ming_ip`）则把它设为 `task.voice`，值为 `灵小萌` / `US_Stella`。

### 9.2 替换现有音频

1. 按 5.2 试生成 3 条，人工确认音色；
2. 全量生成（133 条约 16 分钟）；
3. 校验 `audio-manifest.json` 与音频文件一一对应；
4. 跑 `node scripts/e2e.mjs` 确认播放链路；
5. 归档授权书与生成记录。

### 9.3 不建议的做法

- 不要把克隆音频用于对外宣传素材（超出授权范围）
- 不要为了省事跳过试生成直接批量跑（一旦转录错，133 条全部作废）
- 不要在同一批次里混用不同参考音频（音色会跳变）
